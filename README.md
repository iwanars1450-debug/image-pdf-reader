# Image PDF Reader

画像PDFを縦連続スクロールで読むための、Kotlin製ローカルAndroidアプリです。Android 8.0以上、縦画面・ダークテーマ固定。ROG Phone 6向けに1080px幅の表示を想定しています。

MITライセンスで公開しています。ライセンス全文は [LICENSE](LICENSE) を参照してください。対応端末での実機検証範囲は [VALIDATION.md](VALIDATION.md) に記載しています。

## 開く・ビルドする

Android Studioでこのフォルダを開き、SDK Platform 35 / Build Tools 35.0.0 / JDK 17を用意してGradle Syncを実行してください。Gradle Wrapperを同梱しています。

```powershell
.\gradlew.bat assembleDebug
.\gradlew.bat testDebugUnitTest lintDebug
```

APKは `app/build/outputs/apk/debug/app-debug.apk` に生成されます。直接インストール用のAPKをプロジェクトと一緒に提供します。

署名鍵はGitリポジトリに含めません。クローン後のdebugビルドではAndroidの標準debug鍵を生成して使用します。開発元のローカルに `debug.keystore` がある場合のみ、その鍵を使って既存インストールとの互換性を維持します。正式配布する場合は、自分で管理する署名鍵を使ってください。同じ端末で更新する際はapplicationIdと署名鍵を維持します。異なる鍵のAPKへ変更するには通常アンインストールが必要で、内部ライブラリも消えるため、先にアプリ内バックアップを作成してください。

## 操作

- ホームの＋：新しい作品、PDFの複数インポート、端末フォルダからの一括インポート。
- 親フォルダ内の「追加」：新しい作品フォルダを作成すると1階層だけのサブフォルダになります。PDFとサブフォルダは同じ一覧でソート・手動配置できます。
- サブフォルダ内の「PDFを追加」：単体・複数PDF、選択した端末フォルダ直下のPDFを追加。名前順固定で、さらにフォルダを作成することはできません。
- 長押し：複数選択。操作から名前変更、確認付き削除、共有、書き出し、移動。PDFとサブフォルダを混在選択して一括移動できます。移動先をフォルダから辿り、「ここに移動」→確認の「移動」で実行します。同名項目は連番を付けて両方保持します。親フォルダ自体は移動できません。
- フォルダの冊数と表紙は直下PDFだけが対象です。フォルダの削除は中のサブフォルダ・PDFも対象になることを確認してから実行します。書き出しとバックアップは親子関係を維持します。
- 手動順：長押しメニューでドラッグによる並べ替えを選択。画面上下端へドラッグすると一覧もスクロールします。
- PDF：縦スクロール、ダブルタップで2倍、1本指でパン。ピンチはありません。
- 右端：タップは移動しません。ドラッグ中は本文固定、プレビューを更新し、離すと選択ページの先頭へ移動します。最終ページも先頭に合わせられるよう末尾は空白背景までスクロール可能です。
- 音量＋／−：上下へスクロール。長押しは徐々に加速。音量操作またはFast Scrollを開始すると拡大を解除します。
- 二本指横スワイプ：作品の現在の並び順で前後PDFへ。拡大中は無効です。
- シングルタップ：上部UIとシステムバーを約2秒表示。PDFの表示領域は変わりません。
- 外部アプリの「このアプリで開く」：ライブラリへ追加せず直接閲覧。上部UIから明示的に追加できます。
- 設定：変更は「保存」でまとめて確定。未保存のまま戻ると破棄確認を表示します。

## アーキテクチャ

アプリ実行時の外部ライブラリ依存はありません。Android標準APIとKotlinで構成しています。テストのみJUnitとAndroidX Testを使用します。

| ファイル | 責務 |
|---|---|
| MainActivity.kt | ホーム・作品・検索・設定・オンボーディング、SAF選択UI、ビューアへの遷移 |
| Models.kt | データモデル、設定の検証、数値部分を比較するNatural Sort |
| Library.kt | SQLite、原本コピー、ロールバック、サムネイル、バックアップ／復元、書き出し |
| PdfSession.kt | PdfRendererを専用スレッドで直列実行、画質・メモリ制限、描画要求の優先制御 |
| ReaderView.kt | 連続スクロール、ズーム、慣性、音量入力、二本指ジェスチャー、Fast Scroller |
| ShareProvider.kt | PDF共有のための読み取り専用content URI |

UIはネイティブViewを使用し、グリッド位置と検索状態はActivity内のセッション状態として維持します。プロセス再起動時には一覧位置を復元しません。ファイル処理、描画、サムネイル生成はバックグラウンドで実行します。

### データモデル

- works：UUID、作品名、手動順、更新／閲覧日時、列数、並び替え方式、降順指定、親フォルダID（ホーム上の親フォルダはNULL）。
- books：UUID、所属作品、元のファイル名、総ページ数、手動順、更新／閲覧日時、読書ページ、ページ内の正規化オフセット。
- metadata：アプリ設定、ホームの列数・並び順、最後のPDF、オンボーディング完了。

SQLiteの外部キーと一意制約を使用し、作品削除時は関連PDF情報を削除します。DB version 2への移行では旧SharedPreferencesの設定を移します。現在は設定を含むすべての永続情報をSQLiteで管理し、完全置換の復元では設定とライブラリを同じDBトランザクションで反映します。

DB version 3はworksへNULL許可のparent列と索引・階層検証トリガーを追加するだけです。既存作品はすべて親フォルダとして残し、PDF所属・一意ID・読書位置・設定を移行時に書き換えません。PDF移動はUUIDファイルを動かさず、DB上の所属と配置順だけを一括更新します。サブフォルダ移動はparentを更新するだけで、内包PDFの所属IDは保持します。APIとDBトリガーの両方で孫フォルダと親フォルダの移動を拒否します。

バックアップ形式version 2に親IDを含めます。旧version 1も読み込み可能です。復元前に親の存在と最大1階層を検証し、親→サブフォルダの順でトランザクションに挿入します。詳細と実機検証は [SUBFOLDER_PATCH.md](SUBFOLDER_PATCH.md) を参照してください。

### ストレージ

```text
files/pdfs/<UUID>.pdf         原本のバイト列（変更・再圧縮なし）
databases/library.db         WAL付きSQLite
cache/covers/<UUID>.png      再利用する1ページ目サムネイル
cache/fast-<session>/        セッション専用低解像度プレビュー
cache/restore/              復元ステージング
```

PDFの表示名と物理ファイル名を分離し、名前変更で原本を操作しません。表紙はNatural Sortで最初になるPDFの1ページ目です。サムネイルはセッションをまたいで再利用しますが、Androidのキャッシュ回収で消える場合は再生成します。

### インポートと復元

コピー・検証中のファイルには新しいUUIDを使い、確定前にはDBへ公開しません。既存PDFを置き換える場合も元ファイルを残して準備し、全件成功してからトランザクションで切り替えます。キャンセル・例外時は新規ファイルを削除します。プロセスが途中で終了した場合は、次回起動時にDBから参照されないファイルを回収します。

フォルダ一括取り込みは選択フォルダ直下のPDFが対象です。同名作品は統合せず連番名にします。重複PDFでは置き換え・別名・キャンセルを選択し、以降の重複へ同じ選択を適用できます。

手動バックアップは `library.json` と原本PDFを含むZIPです。再生成可能なキャッシュは含めません。復元は全ファイルとメタデータを検証してから確定します。統合時は作品に新しいUUIDと安全な作品名を付与して既存データを維持します。ZIPのパス、重複エントリー、形式バージョン、ページ数、容量を検証します。外部への書き出しやバックアップ出力自体は、保存先プロバイダーでの失敗時に途中ファイルが残る場合があります。

### 描画・読書位置

ページの縦横比だけをバックグラウンドで取得して連続座標を構築します。起動時に全ページのBitmapを生成しません。現在の表示ページを優先し、前後ページを容量内で先読みします。

高品質BitmapのLRU上限は48MiBまたはアプリヒープ上限の1/8の小さい方。1ページのピクセル予算にも上限を設け、現在の作業集合がキャッシュ上限を超えて描画を繰り返すことを防ぎます。通常の1080px幅ページは画面幅相当で描画し、特に縦長のページや2倍表示ではメモリ予算に応じて描画解像度を制限します。

Fast Scroll用プレビューは幅240px、メモリ4MiB、ディスク128MiBを目安に自動管理します。現在付近・選択ページを優先し、空き時間に残りを生成。本文描画はドラッグ中に発行しません。閉じるとセッションキャッシュを削除します。通常表示では低画質画像を挟まず、背景とスピナーから直接高品質画像へ切り替えます。

読書位置は表示上端のページとページ内の正規化オフセットです。操作停止から350ms後、連続操作中は約1秒ごと、Fast Scroll直後、PDF切り替え前、画面離脱・onPause時に保存します。最終ページが少しでも見えたら、その閲覧セッションの位置は0にリセットします。閲覧バッジは表示しません。

### 標準APIによる制約

- **実行中の描画の中断**：PdfRendererの同期renderには途中キャンセル用APIがありません。キューは最新の表示要求へ差し替え、不要になった描画結果を破棄します。すでに実行中の1回の描画が終わるまで、選択ページのプレビューが待つことがあります。
- **外部URI**：PdfRendererはseek可能なファイル記述子を要求します。一般的な端末内PDFは直接開けますが、一部のクラウド等のストリーム専用プロバイダーは直接開けません。その場合は「PDFを開けませんでした」と表示します。端末へ保存するかライブラリにインポートすれば閲覧可能です。
- **通常UIの互換性**：縦固定とローカルPDFのMIMEハンドラーは仕様どおりです。Lintのwebアプリリンク必須判定は、そのPDFハンドラーに限って抑制しています。

API根拠：[Android PdfRenderer](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer)、[PdfRenderer.Page](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer.Page)。

## 実装フェーズ

Phase 1：ライブラリ、SQLite、SAFインポート、サムネイル。Phase 2：オンデマンド描画と読書位置。Phase 3：ズーム・音量・Fast Scroll・二本指切り替え。Phase 4：検索・並び替え・複数選択・共有／書き出し・外部URI。Phase 5：設定・手動バックアップ／復元・キャッシュ・オンボーディング。Phase 6：ビルド、Lint、単体テスト、接続実機での検証。
